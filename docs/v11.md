# v11 看板 · 批次入库 + 数仓聚合版

v11 已从「单文件 + 浏览器本地状态」改成 **本地数仓 + 单页看板**：
所有金额来自 SQLite（`数仓/v11/warehouse_v11.db`），页面只做展示聚合，不再内嵌数据、不再读本地缓存。

## 一、启动

```bat
打开看板v11.bat            :: 启动服务(8770) 并用默认浏览器打开
:: 或
数仓\v11\open_v11.bat
:: 或手动
.venv\Scripts\python.exe 数仓\v11\server11.py --port 8770
```

- 服务：`数仓/v11/server11.py`（标准库 HTTP，无第三方依赖）
- 库：`数仓/v11/warehouse_v11.db`（首次启动自动建表并灌入种子）
- 重建前端：`.venv\Scripts\python.exe 数仓\build_v11.py`
- 重置数仓：`server11.py --reset`（**会清空库**，只在确需重来时用）

## 二、数据链路（唯一写入路径）

```
申请批次(公司+期间) → 解析校验(表头/重复) → 逐笔落库 flow_raw
        → 规则匹配(match_rule) → 未命中进待确认池
        → 人工确认(状态+反写规则+留痕) → 聚合视图 → 各看板取数
```

| 表 / 视图 | 作用 |
| --- | --- |
| `import_batch` | 流水申请批次：公司、期间、文件、指纹、行数、状态 |
| `flow_raw` | 流水原始表：字段、`code/l1/l2/cf_item`（来自映射表）、`status`、`biz_key`、来源文件/行号 |
| `match_rule` | 匹配规则：优先级、方向、范围、关键词、科目、启用状态、`source=skill/manual_back` |
| `subject_map` | 分类映射：22 项 → 活动类型 → 资金计划科目 → 现金流量表项目 |
| `plan_batch` / `plan_item` | 计划批次与明细：draft → pending → approved |
| `fx_rate` | 汇率（人工维护）：币种对、汇率、生效日期、录入人、录入时间 |
| `audit_log` | 修改留痕：字段、修改前后值、操作人、原因 |
| `v_flow_actual` | 看板实际数视图（`status='confirmed'`） |
| `v_plan_approved` | 预实计划数视图（`status='approved'`） |
| `agg_meta` | 聚合刷新时间（每次写操作后刷新） |

**状态口径**：`draft`（草稿）/ `pending`（待确认）/ `confirmed`（已确认）。
看板只读 `confirmed`；草稿与待确认单独存放、查询过滤，绝不混入。

## 三、页面模块

### 一 · 管理视角
- **集团资金总貌**：可用资金、受限资金、现金流入、现金流出四张卡 + 环比三角（▲红增 / ▼绿减，上期为 0 显示「—」）；可用资金余额趋势（近 12 期月末）+ 流入流出趋势；按公司 / 按银行柱图（点公司名跳透视）；汇率表（人工维护，生效日期，缺失即预警）；账户余额与受限；安全线预警。
- **公司资金透视**：同口径四卡 + 环比、可用余额单列；**资金水位趋势**（最近 8 个月实线 + 未来 3 期按已审批计划净流推算的虚线，预测区间打底，橙色虚线为安全线，点时值直接标注，低于安全线标红）；**逐月收支结构瀑布**（期初 → 二级科目 → 期末，期初由期末倒推保证闭合）；按活动类型与二级科目的结构图；账户余额；本期计划。

### 二 · 数据输入
- **流水归集**：支持 `.xlsx` / `.xls` / `.csv`，可一次选多个文件；`.xls`（含实为 HTML 表格的假 xls）由服务端 `xls_read.py` 用 xlrd 解析后回传二维数组。必须先填「公司 + 期间」才解锁导入 → 表头校验 → 文件级 + 记录级双重去重 → 逐笔落库（命中=已确认、未命中=待确认，批次 `parsed`）。**导入只收所选期间的流水**：文件里其他月份的行会被跳过并计数（解析卡显示「超出期间（已跳过）N 笔（月份）」，前端过滤 + 后端 `import_rows` 兜底），避免一个批次混入多个月份；若文件里完全没有该期间的流水，直接提示且不建批次。
  - **表头识别**：列名按「原样精确 → 去括号精确 → 包含」三级比对，别名覆盖各行对账单写法（招行的 `收(付)方名称` / `收(付)方账号` / `借方金额·贷方金额`、工行的 `入账日期` / `对方单位` / `借贷标志`、通用的 `交易日` / `发生额` / `对方户名` 等）。`本方账号` 列会排除含「对方 / 收付方 / 母子 / 对手方 / 付款方 / 收款方」的表头：工行流水没有本方账号列时留空，不再把对方卡号当本方账号。
  - **判重与字段补全**：`biz_key` 命中即跳过；识别规则升级后同一笔会算出不同 `biz_key`，此时再按「公司 + 日期 + 方向 + 金额 + 摘要 + 文件内行号」认一次，命中就把新识别到的对方户名 / 对方账号 / 余额补回旧行（只补空值、不动已确认科目），重算受限资金标签并刷新 `biz_key`，误填的对方账号就地清空。解析卡显示「重复 N 笔（其中 M 笔补全了对方户名/账号）」，所以规则升级后把原文件重导一次即可修好历史批次。
  - **人工识别**：筛选「未识别 / 已识别 / 全部」，默认未识别；科目分**两列**——一级（经营 / 投资 / 筹资 / 内部往来）+ 二级（按一级联动）。
  - **保存**：只写**有实际变化**的科目，仍为未确认、不进看板；科目没变时不写库、不标脏，提示「没有需要保存的改动」。
    已确认记录被改了科目 → 置「未确认（已修改）」（`status=pending, modified=1`）、批次退回 `parsed`、留痕，重新确认才更新看板；
    与单条「修改」同一口径，不再出现「点一次保存整批已确认记录全变未确认」的死结。
  - **全部确认**：本批所有**已识别**记录一次性置 confirmed（不受筛选影响），写库 + 刷新聚合，提示「已确认并保存至数仓（HH:MM:SS）」；批次状态 parsed → **confirmed**，申请层面只读（显示「已确认」+「查看本批记录」）。
  - 已确认记录仍可**单条修改**：改后置「未确认（已修改）」、批次退回 parsed、留痕；重新确认才更新数仓。
  - **导入即确认**：整批都命中规则（无待确认）时，批次导入后直接置 `confirmed`，不会卡在 `parsed` 而「全部确认」又是灰的。
  - 「确认所选」（`/api/confirm`）也会同步批次计数；本批全部记录确认完才置 `confirmed`。
  - 批次列表含：批次 / 公司 / 期间 / 文件 / 行数 / 已确认 / 待确认 / 状态 / **操作人** / 创建时间 / **最后操作时间**；整行可点，直接打开该批继续识别。
- **资金计划编制**：申请（公司+期间）→ 下载模板（**直接下发源文件 `资金计划表_模板.xlsx`**，不程序生成，格式原样）→ 上传 → 字段/科目映射校验（旧 7 项自动映射到 22 项、占位主体跳过）→ **校验通过即落库为「可编辑」批次**（数据不丢，不进预实）→ 下一步：提交审批 → 审批通过才写入 `v_plan_approved` 并同步预实。
  - 状态机：`parsed`（可编辑）→ `submitted`（审批中，可**撤回**回 parsed，留痕）→ `approved`（已入数仓）；驳回同样退回 parsed 可改重提。
  - 批审批通过后入数仓并参与预实；已审批不允许直接改，**也不生成变更版本**：改数只能「撤回」（该版本立即退出预实）→ 重新导入覆盖同一批次 → 重新提交审批；已审批状态下再次上传会被拦截并提示先撤回。
  - 批次列表含**操作人**与**最后操作时间**、版本号，并按状态给出可执行动作。
  - 可回看：进入计划页自动载入最近一条**已审批**批次（无则最近一条），② 区直接显示该批明细与合计；批次列表每个批次都有「查看」按钮，任意状态均可载入回看。状态以中文展示（可编辑 / 审批中 / 已审批·已入库 / 历史版本 / 已驳回）。

### 三 · 资金穿透（三级穿透 · 打标明细）
① 资金方向（活动类型：经营/投资/筹资/内部往来，取映射表 l1）→ ② 按二级科目分类（按 `l2` 去重后给 chips，带实际金额；点选任一科目即只保留该科目明细，筛选条件与明细同源，避免同一 l2 多 code 重复列 chip、金额恒为 0）→
左「计划 vs 实际」按月正负柱对比 + 右「三级穿透·打标明细」（期间/收+支/收/支/金额阈值/分类/实际流水或计划切换；
列：日期·方向·分类·对方户名·科目·金额；底部收入/支出/净额笔数与金额）。实际 = `confirmed` 流水，计划 = `approved` 计划，同口径不混。
分类 chips 的金额跟随当前数据源（实际流水 / 计划），柱状图每根柱顶标注金额（万元）。

### 三·补 · 受限资金识别与未来三个月水位

- **受限资金**：新增 `restricted_rule`（6 类 26 条关键词：保证金 / 未到期定期存款 / 境外受监管 / 质押存款 / 冻结 / 公管资产），命中摘要或对方户名即给 `flow_raw.restricted_kind` 打标签；**不改科目分类**，映射表 `is_internal=1` 的内部往来不参与识别（两类标签不混用）。导入、人工确认、批量保存、单条修改都会重算。
- 取数：`snapshot.restricted` 按「账户 × 类别」给出受限金额（= 转出 − 退回）、笔数、最后余额与时点、逐笔明细、规则表；只统计已确认流水。
- 页面：集团总貌 / 公司透视各有「受限资金（自动识别）」卡片（4 KPI + 类别 chips + 账户明细 + 逐笔展开 + 规则维护）；可用 = 末笔余额 − 自动受限 − 人工补录（同账户有自动识别时不重复扣人工值）。
- **水位推算**：未来三个月净流入 = 已审批计划净流入 × 12 个月达成率（近 12 个月实际/计划，样本 < 3 个月不校准）；无计划月按近 3 个月实际净流入月均外推并标注；逐月水位 = 当前可用 + 累计净流入，另给逐周水位、最低水位、覆盖月数（可用 ÷ 近 3 个月月均支出）、首次跌破安全线的月份。主体数据滞后时补空月，报告期固定为实际月之后的三个月。
- 页面：公司透视「未来三个月资金水位推算」卡片；集团总貌安全线表新增「未来三月净流 / 三月最低水位 / 击穿预警」。

### 四 · 预实分析
计划（已审批）/ 实际（已确认）对比：总偏差率（绝对额+率）、科目偏差明细（横向双向条 `svgDevBar` + 明细表，按绝对偏差降序、有利/不利、备注）、Top5 贡献度（竖向柱状 `svgTopDev` + 明细表）、方向结构、连续偏差期数、计划执行进度、计划/实际/累计偏差趋势（顶部只留 4 个 KPI：计划合计、实际合计（同期）、总偏差率、连续偏差期数；规则匹配 / 人工确认仅作页脚提示）。

- **口径**：实际只取「有计划月份」的已确认流水（同期可比）；偏差图**只画有计划的可比科目**，无计划科目只在表里标「计划未列该科目」。
- **交互**：偏差条/柱每根都有 `<title>`，悬停显示 计划 / 实际 / 偏差额 / 偏差率；柱尾标 `+/−金额`，零轴给 ±最大偏差刻度。
- **空态**：无计划时提示「没有可比科目 · 需先有已审批计划，且实际落在计划月份」，不画空图。

### 五 · 现金流量表
直接法，按 `subject_map.cf_item` 归并；**内部往来剔除，不计入任何报表项目**，附注写明「已抵销内部往来 N 笔 / 金额 X」；
报表项目按映射表 `cf_section/cf_item` **全量列出**（去重、保持 sort 顺序），当期没有流水的项目记 0 并显示笔数 0，不再整段省略；期初/期末余额缺失时显示「暂无」。Excel / CSV 下载；附注同时标注「尚有 N 笔待确认」。

## 四、口径与约定

1. 实际数 = `confirmed`（规则已匹配 + 人工确认）；草稿/待确认只在待确认区与附注出现；计划数 = `approved`。
2. 活动类型、现金流量表项目、**内部往来/集团抵销标识**一律取自 `subject_map`（`is_internal` / `group_elim`），前端不硬编码。
3. 内部往来全链路：现金流量表**剔除**；预实分析**同口径剔除**后算偏差；集团资金总貌**汇总抵销**（页头显示抵销笔数/金额）；公司资金透视**保留**并标注「含内部往来 N 笔 / 金额」；资金穿透保留该分类可下钻。
4. 汇率人工维护、**不联网**；历史期间用期间末生效汇率，缺失时该主体折算显示「汇率缺失」并预警。
5. 余额：每账户取期间末最后一条带余额的流水；无逐笔余额账户不参与期初期末。
6. 人工确认时按对手方反写一条低优先级精确规则（`source=manual_back`），可在规则表停用。

## 五、接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/api/meta` | 主数据、映射表、汇率、批次、计数、聚合时间 |
| GET | `/api/snapshot?entity=&period=` | 看板统一取数（行 + 余额 + 计划 + 汇率） |
| GET | `/api/pending` / `/api/batch-rows` | 待确认池 / 本批全部记录 |
| POST | `/api/batch` | 建申请（公司+期间+文件指纹） |
| POST | `/api/import` | 逐笔落库（`submit=false` 存草稿） |
| POST | `/api/confirm` | 人工确认（状态+反写规则+留痕+聚合刷新） |
| POST | `/api/edit` | 单条修改（置待确认，留痕） |
| POST | `/api/flow/save` | 人工识别「保存」（只写有变化的科目、仍为未确认；返回 `saved`/`changed`） |
| POST | `/api/flow/confirm-batch` | 「全部确认」：本批已识别记录整批置 confirmed |
| GET | `/api/flow/batch?batchId=` | 批次状态（confirmed / parsed、确认时间） |
| POST | `/api/plan` | 计划上传落库（`parsed`，可编辑、不进预实） |
| POST | `/api/plan/submit` / `withdraw` / `reject` | 提交审批 / 撤回 / 驳回 |
| POST | `/api/plan/approve` / `change` | 审批入库（覆盖同期间旧版）/ 发起变更生成新版本 |
| GET | `/api/plan-batch?batchId=` | 计划批次明细（含版本、状态） |
| GET | `/api/plan-template` | 下载源模板 `资金计划表_模板.xlsx` |
| POST | `/api/fx` / `/api/safe` / `/api/restricted` | 汇率 / 安全线 / 受限资金维护 |
| POST | `/api/parse-file?name=文件名.xls` | 旧版 `.xls` / 假 xls 解析（原始字节，返回二维数组）。文件名走查询串，避免自定义请求头触发 CORS 预检 |
| POST | `/api/reset-data` | 清空业务数据（保留主数据/映射/规则/汇率） |

`period` 支持 `CUR`（当月）/`L3M`/`YTD`/`ALL`/`Q1..Q4`/`YYYY-MM`。
区间口径：`CUR`/`L3M`/`Qn` 以**最新确认流水月**为基准；`YTD` 为当年 1 月起到「流水或已审批计划的最大月份」（同年内），保证只上传了后续月份计划时也能落在区间内；`ALL` 取流水与计划的最早~最晚月份。

- 测试库用 `V11_DB` 环境变量指向 `tmp/test11.db`，不污染工作库。
