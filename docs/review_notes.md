# 文档与实现核对

核对日期：2026-11-17。范围包括 Python 服务/解析/数据库、HTML/JS 页面、SQL、启动脚本和测试。相关语言均可直接检查，无因语言不支持而跳过的模块。

## 已校正的历史描述

- 代码当前是「提交 → 批准」两个操作，历史文案中的待批/复核通过不是当前有效状态路径。
- 页面不能依赖内嵌历史数据，发布版数据为空，启动后从本地 API 读取。
- 模板由当前配置生成；不再声称不存在的本地 Excel 原件可以直接下载。
- 审批角色是留痕字段，不是登录和权限系统。
- 参数可保存不代表已经参与所有算法；功能文档已列出预留项。
- 数仓 Excel 导出不是完整备份，完整恢复需要数据库和上传原件。

## 发布适配验证

用临时空库验证初始化、空模板、主体/客户无记录、重启保留用户参数、附页存储。API 回归使用自动构造工作簿，覆盖上传、审批、核销、汇率和人工确认。前端回归覆盖保存失败、刷新、连续编辑及全部页面渲染。发布检查核对待上传文件和内嵌数据；验证结果以当前 CI 及本地测试输出为准。

## 已知限制与后续方向

- 多步骤审批、锁定同步和变更尚未使用单一业务事务，也没有并发审批锁；不适合多人并发部署。
- 业务键不是银行交易唯一号，同日同金额同对手可能共享人工标签。
- 已核销后再次提报的版本替换策略需完善；G3 为报告提示，不能声称有完整三级强制审批。
- 旧季度利润报表仍有历史月份、季度模型和独立页面参数；无历史预算的发行版需用户自行配置，不能视为自动形成真实利润表。
- 客户新增、部分配置管理依赖 API/模板；不是所有后台能力都有完整 UI。
- 上传原件匹配、无效请求处理、用户权限、数据隔离、浏览器草稿容量等仍可改进。没有统一承诺所有任意格式的银行和预算文件均可识别。

后续维护以功能清单为基线，避免把历史设计目标直接写成已完成能力。
