# 功能清单与实现状态

## 已实现的操作与计算

| 功能 | 当前能力 | 入口与边界 |
| --- | --- | --- |
| 银行流水接入 | XLSX/CSV 多文件导入、表头定位、字段别名、日期/金额规范化、导入记录、去重 | 数据接入；`.xls` 须先另存为 XLSX/CSV |
| 自动打标 | 按优先级、收支方向、对手/摘要/科目关键词、金额区间匹配规则 | 可新增/编辑/停用规则；对话式规则助手使用本地解析，不调用大模型 |
| 人工确认 | 一级/二级/现金流类别修改、筛选、批量保存、仅修改局部标签 | 已确认结果落库；失败保留草稿并提示 |
| 存档流水修正 | 修改字段、保留人工分类、改键迁移、修改历史 | 用户必须确认修改原因与操作人等业务内容 |
| 导入追踪 | 导入申请、状态确认、文件与批次显示 | 重置预览不会删除数据库记录 |
| 管理视角 | 收支、净流、余额、安全线、趋势、按分类汇总 | 旧界面部分季度标签仍保留，跨期应结合生态模块核对 |
| 下钻与收支明细 | 按类别/月份/方向/关键词/金额筛选，查看大额明细 | 依赖用户导入的流水或有效计划 |
| 旧预实分析 | 分类覆盖率与计划/实际差异 | 历史内嵌客户比较输入已清空；推荐使用生态比对 |
| 报表与导出 | 月度/季度情景、资金计划、摘要、CSV；数仓 Excel 导出 | 利润情景依赖手工参数，发布版不预置历史预算 |
| 模板管理 | 注册展示、下载计数、动态空白预算/流水 XLSX | 不再依赖本地历史样例；未提供原件的旧模板不注册 |
| 标准计划上传 | 解析预算明细、主体/科目/汇率；保留原件、附页和源行；选择期间 | 文件名月份与所选期间不一致会提示；不自动改写期间 |
| 源预算转换 | 销售/部门费用/人力源表按 C-01 至 C-09 拆成月度计划 | 需要唯一主体或明确传入主体，多主体使用标准计划表 |
| 审批与版本 | 草稿、提交、待审、批准锁定、退回、发起变更、核销、日志 | 无用户认证；角色字段不是访问权限 |
| 主数据 | 科目字典、主体台账、币种及汇率随标准模板导入合并 | 主体/客户不预置，台账字段需完整填写 |
| 业务参数 | 参数保存、客户账期（含 0 天）、桥接启停与补规则 | 部分参数只是存储或提示，详见下表 |
| 滚动预测 | 有效计划 × 回款比例/账期/采购付款延迟；期初余额+累计净流 | 默认最近有效计划期间起算；缺上月余额不判断安全线 |
| 生态预实比对 | 按期间、主体和科目桥接比对；同期/账期/滚动窗口；差异分级、未匹配清单、体检、CSV 导出 | 属于规则汇总匹配，不保证银行交易逐笔自动核销 |
| 匹配留痕 | `/api/match-link` 可保存人工关联 | 尚未形成完整自动逐笔核销闭环 |
| 数仓工具 | `/db` 表预览、`/api/health` 健康状态、ETL 导入/导出 | Excel 导出只覆盖流水、旧计划和人工标签，不等同完整备份 |

## 业务参数的实际用途

| 参数 | 已接入的位置 |
| --- | --- |
| `fx.币种` | 计划上传折人民币，优先于模板汇率；新币种从模板汇率补建参数 |
| `th.big_amount` | 计划大额缺备注提示 |
| `term.default`、客户 `term_days` | 滚动预测和账期比对窗口 |
| `term.purchase_lag` | 预测采购付款后移 |
| `collect.month_ratio` | 预测当月回款与后续回款分配 |
| `safe.line` | 预测期末余额预警；默认 0，使用前填写 |
| `fc.horizon` | 预测期数 |
| `th.var_ok`、`th.var_ok_abs`、`th.var_warn` | 生态比对差异分级 |
| `th.tag_rate`、`th.map_rate`、`th.cust_hit` | 生态比对体检阈值 |
| `gate.allow_placeholder` | 解析时生成占位主体提示；不是独立的强制审批闸门 |
| `term.ka_default`、`term.window_mode`、`collect.bad_debt`、`safe.months`、`safe.late_out_ratio`、`th.recon_diff`、`scope.include_non_ka`、`tax.basis` | 参数中心可存储/展示或预留；未完整驱动对应算法，不能仅凭参数名称推断行为 |

实际比对窗口由页面选择控制；源表转换的非 KA 排除按 C-02 固定逻辑执行。旧利润情景中的税率与费用参数属于另一套页面模型，不能等同生态参数中心持久化配置。

## 校验与审批边界

G1 检查必填、字典、金额；部分问题仅警告。G2 对重复行及字典外语汇拦截，内部调拨不平生成报告。G3 生成勾稽、占位、版本提示；当前提交检查 G1，批准检查 G2，G3 不是独立审批步骤。失败的有效闸门可通过显式 `force=true` 强制推进并留痕。

批准会替换同期间同主体的旧「已锁定」版本；已核销记录仍用于取数。已核销期间再次提交新版本的业务策略尚未完整约束，操作前应人工核对，不能假设已自动避免重复计入。

多用户认证、并发审批事务、冲突合并、自动定时预测、云同步、OCR 和在线大模型服务未实现。
